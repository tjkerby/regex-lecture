We need a way to describe the strings we want to find, rather than list them one at a time.

A regex describes a set of strings

Alma 7:12 is one value. The pattern Alma \d+:\d+ describes many:

Alma 7:12     ✓
Alma 34:32    ✓
John 8:31     ✗

The book and punctuation stay fixed. The chapter and verse can change. Here \d stands for a digit, and + means one or more of the preceding item. We will work through those pieces before asking you to build a pattern.

How we build larger patterns

A regex is made from a few types of instructions:

Instruction What it lets us describe
Exact text A fixed book name or punctuation mark
A choice One allowed character or one allowed word
Repetition A chapter with one, two, or more digits
Position The beginning of a field or a word boundary

Putting instructions next to each other describes their order. We will learn the notation for each one in the next few examples.

Searching and checking a whole field

re.search() finds a pattern inside a string. re.fullmatch() checks whether the entire string fits.

Our pattern is the literal text "cat". We wrap each result in bool() so the answer is True if there is a match and False otherwise. What will these three checks return?

import re

bool(re.search("cat", "The cat slept"))
bool(re.fullmatch("cat", "The cat slept"))
bool(re.fullmatch("cat", "cat"))

Predict with a neighbor, then compare with the next slide.

Check: search versus fullmatch

search("cat", "The cat slept")     → True
fullmatch("cat", "The cat slept")  → False
fullmatch("cat", "cat")            → True

We used bool() to ask whether a match exists. A search can succeed even when the whole field does not fit the rule.

Literal characters and the dot

Most characters match themselves. Some have special meanings.

r"byu.edu": the dot matches almost any character.

r"byu\.edu": the escaped dot matches a literal period.

The r tells Python to pass the backslash to the regex engine. We will write patterns as raw strings from here on.

With a neighbor: Which pattern accepts byuXedu? Which accepts byu.edu?

Check the dot

values = ["byu.edu", "byuXedu"]
for pattern in [r"byu.edu", r"byu\.edu"]:
    print(pattern, [bool(re.fullmatch(pattern, v)) for v in values])
byu.edu   [True, True]
byu\.edu  [True, False]

Escaping changes a special character back into the literal character.

Character classes choose one character

[.-] matches one dot or hyphen. A range such as [A-Z] matches one capital letter.

We can combine ranges: [A-Za-z0-9] matches one letter or digit. We will use that in the email exercise.

r"801[-.]555"   matches   801-555   and   801.555

Inside [ ], a dot usually has its ordinary meaning. Outside, . is a wildcard.

Predict: Would [.-] match the two-character string .- as a whole field?

A negative character class

[^aeiou] means one character other than a lowercase vowel.

[bool(re.fullmatch(r"[^aeiou]", x)) for x in ["a", "b", "7"]]
[False, True, True]

It also accepts 7. “Not a vowel” is broader than “a consonant.”

Useful shorthand classes

Pattern One matching character
\d digit
\s whitespace, including many spaces that look ordinary
\w word character, including letters, digits, and _
\D, \S, \W the corresponding opposites

\w is convenient, but it may include characters your task did not intend. In Python, it can also include Unicode letters.

Quantifiers change how many

Pattern Number of repetitions Example
\d{3} exactly 3 801
\d{2,4} 2 to 4 12, 8421
\d+ at least 1 7, 343
\d* 0 or more "", 77
u? 0 or 1 color, colour in colou?r

A quantifier acts on the item immediately before it. That item can be a character or a class. On the next slides, we will make a whole group count as one item.

Groups choose whole alternatives

(?:red|blue) car allows red car or blue car.

[(v, bool(re.fullmatch(r"(?:red|blue) car", v)))
 for v in ["red car", "blue car", "red truck"]]
[('red car', True), ('blue car', True), ('red truck', False)]

(?: ... ) groups a choice. | separates the alternatives. We will use a named capturing group tomorrow when we need an extracted column.

A class and a group are different

Pattern Its choice
[cd] one character, c or d
(?:cat|dog) one word, cat or dog

Predict: Does [cat|dog] match the whole word cat? Why might it still find something inside cat with re.search?

Check the class and the group

print(bool(re.fullmatch(r"[cat|dog]", "cat")))
print(re.search(r"[cat|dog]", "cat").group())
print(bool(re.fullmatch(r"(?:cat|dog)", "cat")))
False
'c'
True

[cat|dog] still consumes one character. For whole words, choose between groups of characters.

Pause: what is being repeated?

Compare these patterns on the whole string hahaha!:

r"ha+!"       # repeat the a
r"(?:ha)+!"   # repeat the group ha

Think, then pair: Which one matches? What string might the other match instead?

Check the quantifier’s scope

[(p, bool(re.fullmatch(p, "hahaha!")))
 for p in [r"ha+!", r"(?:ha)+!"]]
[('ha+!', False), ('(?:ha)+!', True)]

ha+! accepts haaa!. (?:ha)+! accepts hahaha!.

The parentheses determine what the + repeats.

Positions are different from characters

Position Meaning in today’s examples
^ start of the string
$ end of the string
\b boundary between a word and a nonword character

These symbols do not consume a character. A word boundary can occur next to punctuation, not only next to a space.

For a whole field, re.fullmatch() often states our question more directly than adding ^ and $.

One phone rule and its limits

import re

phone = r"(?:\d{3}[-.]|\(\d{3}\) )\d{3}[-. ]\d{4}"
values = ["801-555-0142", "801.555.0142", "(801) 555 0142",
          "(801 555 0142", "8015550142"]
for value in values:
    print(value, bool(re.fullmatch(phone, value)))
801-555-0142 True
801.555.0142 True
(801) 555 0142 True
(801 555 0142 False
8015550142 False

New test: It also accepts 801-555.0142. Would that matter for your data?

A choice is different from an option

For an email written two ways, we need a separator in each position. We choose which form it takes:

Choice Matches
(?:@| \(at\) ) @ or (at)
(?:\.| \(dot\) ) . or (dot)

There is no ? here: omitting the separator would make an invalid address. The spaces around (at) and (dot) are part of those choices.

One email rule and a decision

email = (r"[A-Za-z0-9]+(?:@| \(at\) )[A-Za-z]+"
         r"(?:\.| \(dot\) )com")
values = ["tom@byu.com", "tom (at) byu (dot) com",
          "amy7@gmail.com", "tom@byuXcom", "tom at byu dot com"]
for value in values:
    print(value, bool(re.fullmatch(email, value)))
tom@byu.com True
tom (at) byu (dot) com True
amy7@gmail.com True
tom@byuXcom False
tom at byu dot com False

This rule also accepts tom@byu (dot) com. If that mixture is not meaningful, we could check for it or standardize the written-out form in a data pipeline first.

Group challenge 3: verse ranges

Yesterday’s John/Alma board rule was (?:John|Alma) \d+:\d+. Keep single verses and allow ranges too.

Accept as whole fields Reject
John 8:31 John 8:31–
John 8:31-32 Mosiah 3:19

All groups: Which whole piece should be optional? A range can use a hyphen or an en dash. 3 minutes, then defend your pattern.

One rule for one verse or a range

short_citation = r"(?:John|Alma)\s+\d+:\d+(?:[-–]\d+)?"
values = ["John 8:31", "John 8:31-32", "Alma 34:32–33",
          "John 8:31–", "Mosiah 3:19"]
for value in values:
    print(value, bool(re.fullmatch(short_citation, value)))
John 8:31 True
John 8:31-32 True
Alma 34:32–33 True
John 8:31– False
Mosiah 3:19 False

(?:[-–]\d+)? makes the dash and ending verse digits optional together. \s+ accepts a space between book and chapter.

Finding text changes the question

re.fullmatch checks one entire field. re.findall returns the exact substrings found inside longer text.

text = "John 8:31–32; Alma 34:32–33"
old_rule = r"(?:John|Alma) \d+:\d+"
print(re.findall(old_rule, text))
print(re.findall(short_citation, text))
['John 8:31', 'Alma 34:32']
['John 8:31–32', 'Alma 34:32–33']

Tell a partner: Why were the old matches plausible but incomplete? A good match test checks the entire returned substring.

Add the numbered book

book = r"(?:John|Alma|Mosiah|(?:1\s+)?Nephi)"

(?:1\s+)?Nephi handles 1 Nephi and Nephi. The \s+ also handles the nonbreaking space in 1 Nephi from our talk text.

Add names and abbreviations

book = (
    r"(?:John|Alma|Mosiah|(?:1\s+)?Nephi|"
    r"D&C|Doctrine and Covenants|"
    r"Matt(?:hew|\.))"
)

D&C and Doctrine and Covenants are two complete alternatives. Matt(?:hew|\.) shares the Matt prefix, then chooses hew or a literal period.

chapter_verse = r"\d+:\d+(?:[-–]\d+)?"

A test that challenges our rule

print(re.findall(citation, "2 Nephi 9:14; John 8:31–"))
['Nephi 9:14', 'John 8:31']

Neither substring is the complete reference we intended to extract. \b does not prevent a match beginning after 2 or ending before a dash.
